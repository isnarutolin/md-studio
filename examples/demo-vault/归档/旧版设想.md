# 旧版设想（已废弃）

[← 索引](../README.md)

一开始想做成 Electron 桌面应用，后来发现浏览器就够用了。

## 当时的方案对比

| 方案 | 优点 | 缺点 |
| :--- | :--- | :--- |
| Electron | 生态成熟、能读任意路径 | 安装包 100MB+ |
| Tauri | 体积小、性能好 | 要 Rust 工具链 |
| 纯浏览器 | 零安装、立刻能试 | 受 File System Access API 限制 |

## 为什么最后先做浏览器版

1. 改一行代码就热更新，调手感特别快
2. 你可以直接把链接发给我，我打开就能复现问题
3. 核心渲染逻辑是纯 TypeScript，换壳不用重写

## 什么时候必须上桌面壳

- 需要文件监听（别的编辑器改了文件，这边要自动同步）
- 需要吃任意本地路径（图片散落在工作区外）
- 需要系统级窗口、全局快捷键

这三条目前都是硬伤，但都不影响先把渲染手感和浏览流程打磨好。

---

> 结论：**先浏览器，后桌面壳。** 顺序反了会在还没想清楚交互的时候就先花两周配环境。
